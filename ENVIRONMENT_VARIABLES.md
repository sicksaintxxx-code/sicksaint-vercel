# SICKSAINT Environment Variables

Use only the variables required for each service. `.env.example` files contain placeholders; do not copy real credentials into Git, ZIPs, or chat.

## Next.js frontend

| Variable | Scope | Notes |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | Public | Canonical website URL. |
| `NEXT_PUBLIC_FIREBASE_API_KEY` | Public Firebase Web config | Existing Firebase Web App in project `sicksaint`. Public identifier; restrict its API usage in Firebase/Google Cloud. |
| `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` | Public Firebase Web config | Existing Web App Auth domain. |
| `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | Public Firebase Web config | Must be `sicksaint`. |
| `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET` | Public Firebase Web config | Existing bucket identifier; no upload flow is currently verified. |
| `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID` | Public Firebase Web config | Existing Web App setting. |
| `NEXT_PUBLIC_FIREBASE_APP_ID` | Public Firebase Web config | Existing Web App setting. |
| `NEXT_PUBLIC_FIREBASE_MEASUREMENT_ID` | Public, optional | Analytics ID; no Analytics event use was found. |
| `LARAVEL_API_URL` | Server-only binding | In Vercel, generated by the private Laravel service binding. Locally use the Laravel origin, e.g. `http://127.0.0.1:8000`. Do not expose a backend service-account credential here. |
| `WORDPRESS_SITE_URL`, `WORDPRESS_API_URL` | Server-side app config | Required only when using the editorial CMS. The current build's REST calls failed. |
| `WORDPRESS_WEBHOOK_SECRET` | Server secret | Used for webhook validation, if enabled. |
| `UNSPLASH_ACCESS_KEY` | Server secret, optional | Used only by image search helper. |

Firebase Web config is not a service-account key. Do not add `databaseURL`; the application does not use Realtime Database.

`frontend/src/lib/firebase-admin.ts` contains a server-only Firebase Admin SDK initializer that expects `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, and `FIREBASE_PRIVATE_KEY`. Repository search found no call sites, and these vars are not present in `frontend/.env.example`. Do not configure a second Admin credential path solely for this unused helper; Laravel is the selected server boundary. If a Next.js server route later calls it, review that architecture and secret scope first.

## Laravel backend

| Variable | Scope | Notes |
|---|---|---|
| `APP_KEY` | Secret | Generate privately per environment; required by Laravel. |
| `APP_ENV`, `APP_DEBUG`, `APP_URL` | Backend config | Production should use `APP_ENV=production`, `APP_DEBUG=false`, and the configured API origin. |
| `FRONTEND_URL` | Backend config | Permitted frontend origin for CORS. Same-origin BFF is used in Vercel; still configure local/staging origins intentionally. |
| `FIREBASE_PROJECT_ID` | Server config | Must be `sicksaint`; used for Firestore requests and Firebase ID-token issuer/audience checks. |
| `FIREBASE_CREDENTIALS_JSON` | Private secret | Server-side service account JSON passed as a secret variable; never prefix with `NEXT_PUBLIC_`. Needed for Laravel server Firestore access. |
| `GOOGLE_APPLICATION_CREDENTIALS` | Private path, alternative | Use only if a secure credential file is mounted/provisioned in the runtime. A workstation path will not exist in a Vercel container. |
| `FIRESTORE_EMULATOR_HOST` | Local/test only | Optional emulator host. Must remain unset in production. |

Laravel currently uses `google/auth` with its Firestore REST adapter and a custom RS256/JWK ID-token verifier; it does not currently include a Firebase Admin SDK package. Choose one backend credential method. The Firebase ID-token verifier uses Google's public signing keys and does not require a private key; Firestore server access does require the backend credential/IAM permission. In this working folder, `FIREBASE_PROJECT_ID` is set to `sicksaint` only in `.env.example`; `FIREBASE_CREDENTIALS_JSON`, `GOOGLE_APPLICATION_CREDENTIALS`, and `APP_KEY` are blank examples and no backend `.env` exists. No runtime/Vercel secrets were inspectable.

## Removed from the active auth setup

`JWT_SECRET`, the unused Next.js Firebase Admin credentials, and `DATABASE_URL` are not needed by the intended Firebase-to-Laravel request path. Prisma schema/code remnants remain in the source tree as legacy material but the account/admin API handlers are disconnected from Prisma. Do not configure the old variables for a new deployment; the complete retirement of legacy Prisma files/data is still a release blocker and must be planned without destroying local records.
